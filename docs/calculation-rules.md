# 계산 규칙

이 문서는 Myeong 이 **무엇을 어떤 기준으로 계산하는지** 적는 곳이다.
코드도 카탈로그(`data/rules/rules.ts`)도 같은 내용을 각각 다른 형식으로 들고 있다.

- 코드: `core/**` — 실제로 계산한다.
- 카탈로그: `data/rules/rules.ts` — `RULE_XXX_NNN` 로 설명한다. 화면의 "규칙 카탈로그" 에서 그대로 보인다.
- 이 문서: 사람이 읽는 설명. 규칙의 **출처와 경계 사례**를 적는다.

> **한 가지 기준만 쓴다.**
> 명리학은 같은 개념에도 여러 학교가 있다. 이 프로젝트는 목적을 하나씩 정해서 고른다.
> 두 학교를 섞지 않는다. 섞으면 "이 프로그램이 무엇을 말하는지" 답할 수 없게 된다.
> 선택하지 않은 쪽을 쓰고 싶다면 규칙을 추가하는 방식으로 해야 하며, 섞어 쓰면 안 된다.

## 0. 시간 — 무엇을 "기준"으로 삼는가

| 항목 | 기준 | 규칙 ID |
| --- | --- | --- |
| 표준시 | 한국 표준시 KST = UTC+9 고정 | `RULE_TZ_001` |
| 서머타임 | 1948·1951·1987·1988년만 UTC+10 | `RULE_TZ_001` |
| 진태양시 | **보정하지 않는다** | `RULE_TZ_001` |
| "오늘" | `todayInKorea()` 한 곳에서만 구한다 | `RULE_TZ_001` |

**KST 는 상수다.** `new Date().getHours()` 같은 값을 쓰면 브라우저·운영체제 시간대에 따라
같은 순간이 다른 날짜가 된다. 그래서 **"한국의 오늘"은 `core/calendar/koreaTime.ts` 의
`todayInKorea()` 한 곳에서만** 만든다. 웹 화면과 이메일 작업이 모두 이 함수를 부른다.

경계 사례를 코드에서 직접 확인한다.

```
UTC 2026-09-26 15:00  =  KST 2026-09-27 00:00   ← 이 순간부터 "오늘"이 바뀐다
UTC 2026-09-26 14:59  =  KST 2026-09-26 23:59
```

**서머타임은 예외다.** 1948년 6월 1일 ~ 9월 13일, 1951년 6월 1일 ~ 9월 9일,
1987년 5월 24일 ~ 10월 24일, 1988년 5월 8일 ~ 10월 24일은 UTC+10이었다.
이 구간 안에서 태어난 사람의 벽시계 시각은 1시간씩 앞당겨 읽어야 한다.

**진태양시(眞太陽時)는 보정하지 않는다.** 경도(經度)에 따라 실제 태양 시각이 달라지지만,
고전 사주에서도 기준이 갈린다. 여기서는 **벽시계 시각 그대로** 쓴다. (한쪽을 정해 일관되게)

## 1. 절기 — 월주·년주의 경계 (`RULE_TERM_001` ~ `RULE_TERM_003`)

### 1.1 어떻게 구하는가

1. Meeus **저정밀도 겉보기 태양 황도** 식으로 태양의 겉보기 경도를 구한다.
   겉보기(光 apparent)라는 이유는 대기 굴절을 포함하기 때문이다.
2. **행성 섭동 보정**을 더한다.
3. 목표 황경(黃經)에 도달하는 시각을 역추적한다. (이분법)
4. 시각 ↔ 역으로 흐르는 시간을 **ΔT** 로 보정한다.

ΔT 는 Espenak–Meeus 다항식(`TT − UT`)이다. 참조값:

| 연도 | ΔT(초) |
| --- | --- |
| 1900 | −2.790 |
| 1920 | 21.200 |
| 2000 | 63.860 |
| 2026 | 75.075 |

주의할 점 두 가지.

- **ΔT 는 과거에 음수였다.** 1900년 전후의 값이 음수인 것은 버그가 아니라 실제 값이다.
- **연속성이 항상 단조 증가하지 않는다.** 1929 → 1930 이 실제로 0.034초 감소한다.
  그래서 연속성 테스트의 허용 폭을 0 이 아니라 **2.5초** 로 두었다.

### 1.2 정확도는 어느 정도인가

독립 기준으로 **香港天文台(HKO)** 24절기 자료(2020–2027, 192건)와 비교한다.

> **주의 — HKO 자료는 KST 가 아니라 HKT(UTC+8)다.**
> 이 차이(1시간)를 빼먹으면 최대 60분의 어긋남으로 보인다. 처음 이 차이를 놓쳤을 때
> "최대 73분 오차"라는 잘못된 수치가 나왔었다.

비교 결과:

| 지표 | 값 |
| --- | --- |
| 최대 오차 | **13.93 분** (2025년) |
| 평균 오차 | **3.60 분** |
| 날짜 일치 | **192 / 192** (오차로 날짜가 바뀌는 경우 없음) |

연도별 최대 오차:

| 2020 | 2021 | 2022 | 2023 | 2024 | 2025 | 2026 | 2027 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 8.14 | 6.63 | 13.43 | 8.93 | 5.97 | 13.93 | 7.19 | 7.28 |

(단위: 분)

**이 오차는 사주에서 얼마나 중요하나.** 입력을 2시간 단위(시진)로 받기 때문에,
절기 시각이 14분 어긋나도 **시진이 바뀌려면 경계에서 14분 안에 태어나야 한다.**
192건 중 날짜조차 틀린 경우가 없고 시진이 뒤집힌 경우도 없다.
그래도 경계일을 다룰 때는 이 오차를 감안해 절기 당일과 직전일을 함께 검증한다.

기준 자료는 저장소에 함께 둔다: `tests/fixtures/hko-solar-terms-2020-2027.json`.
다시 받으려면 `npm run tools:hko`.

### 1.3 12 節만 월주를 바꾼다 (`RULE_TERM_003`)

24절기 가운데 **절(節)** 12개만 지를 옮긴다.

| 절 | 지 | 절 | 지 |
| --- | --- | --- | --- |
| 입춘 | 寅 | 입추 | 酉 |
| 경칩 | 卯 | 백로 | 戌 |
| 청명 | 辰 | 한로 | 亥 |
| 입하 | 巳 | 입동 | 子 |
| 망종 | 午 | 대설 | 丑 |
| 소서 | 未 | 소한 | 寅 |

중기(中氣) — 우수, 춘분, 곡식, 소만, 하지, 대추, 추분, 서한, 소설, 동지 — 는 **절지를 옮기지 않는다.**
계절의 성격만 정한다.

**경계 사례.** 대설(22번째 절기) 다음은 소한(0번째 절기)이므로 절기 인덱스가 **2만큼** 뛴다.
월주 경계 연속성 테스트는 이 점프를 허용한다.

## 2. 음력 ↔ 양력

### 2.1 사용하는 표

1900–2100년 음력표(`data/lunar/lunarInfo.ts`, 201개 항목)를 쓴다.
표는 **UTC+8 기준**으로 만들어진 표준 표다.

- 지원 범위: **1900-01-31 ~ 2100-12-31**
- 표 밖의 날짜는 `RangeError` 로 즉시 거절한다. (조용히 틀린 값을 내지 않는다)

### 2.2 윤달 (`中氣` 판정)

윤달은 **중기(中氣)** 가 들어오지 않는 달이다. 이 프로그램은 **UTC+8** 로 중기 유무를 판정한다.
(음력표의 기준과 맞추기 위해서다. KST로 판정하면 1900–2100 간 일부 연도의 윤달이 뒤집힌다.)

**가짜 윤달(假閏月).** 실제로는 윤달이 없는데 윤달로 세어야만 음력 날짜가 맞아지는 해가 4개 있다.

```
1985년 1월 · 2033년 8월 · 2034년 1월 · 2053년 1월
```

이 네 곳을 테스트로 고정한다. 윤달 판정 한 글자가 틀어지면 그해 음력 날짜 전체가 어긋난다.

### 2.3 음력을 넣으면 양력을 먼저 보여준다

음력 입력 시 변환 결과를 해석보다 **먼저** 화면에 보여준다. (날짜를 잘못 넣은 걸 숨기지 않기 위해)

## 3. 네 기둥 (사주팔자)

| 기둥 | 기준 | 규칙 ID |
| --- | --- | --- |
| 년주 | 입춘 이후의 해. `(절기년 − 1984) mod 60` | `RULE_YEAR_001` |
| 월주 | 12 節 + 五虎遁 | `RULE_MONTH_001` |
| 일주 | 정수 JDN. `(JDN + 49) mod 60` | `RULE_DAY_001` |
| 시주 | 五子遁 + 12시진 | `RULE_HOUR_001` |

### 3.1 년주 — 입춘이 1월 1일이 아니다 (`RULE_YEAR_001`)

**입춘(立春)이 지나야 그 해의 간지로 넘어간다.** 양력 1월 1일을 기준으로 하면 안 된다.

```
2024-01-01  →  년주 癸卯        (아직 입춘 전)
2024-02-05  →  년주 甲辰        (입춘 후)
```

### 3.2 월주 — 五虎遁 (`RULE_MONTH_001`)

월지의 천간은 **절기년의 천간**에서 五虎遁으로 정한다.

```
인월(寅月)의 천간 = (절기년 천간 인덱스 % 5) × 2 + 2
```

| 절기년 천간 | 갑 | 을 | 병 | 정 | 무 | 기 | 경 | 신 | 임 | 계 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 인월 천간 | 丙 | 戊 | 庚 | 壬 | 甲 | 丙 | 戊 | 庚 | 壬 | 甲 |

### 3.3 일주 — JDN 규칙 (`RULE_DAY_001`)

```
간지 인덱스 = (JDN + 49) mod 60        (0 = 甲子)
```

검증 기준:

```
1949-10-01 → JDN 2433191 → 甲子 (0)
2000-01-01 → JDN 2451545 → 戊午 (54)
2024-01-01 → JDN 2460311 → 甲子 (0)
```

### 3.4 시주 — 五子遁 (`RULE_HOUR_001`)

```
자시(子)의 천간 = (일주 천간 인덱스 % 5) × 2
시주 천간 = (자시 천간 + 시진 인덱스) mod 10
```

### 3.5 자시 — 두 학교 중 하나를 고른다 (`RULE_ZI_001`)

자시(23:00–01:00)는 자정을 지나는 하나의 지지만, 날짜가 바뀌는 기준은 둘이다.
이 프로그램은 **입력에서 선택받는다.** 자동 판정하지 않는다.

| 선택 | 대표 시각 | 일주 날짜 |
| --- | --- | --- |
| **조자시** (23:30 환산) | 23:30 | **생일 + 1일** |
| **자정** (00:30 환산) | 00:30 | **생일 그대로** |

이 선택은 **자시를 고른 경우에만** 화면에 나온다. 다른 시진을 고르면 물을 필요가 없다.

### 3.6 출생시간을 모르면 (`RULE_HOUR_001`)

시주를 계산하지 않는다. 대신:

- 시주 자리를 **미상** 으로 표시한다.
- 해석을 **제한된 범위**로 내려간다. (시주에 근거한 상호·관성 해석을 내지 않는다)
- 화면·이메일에 **제목 없이 알리지 않는다.** 반드시 눈에 보이는 통지가 붙는다.

## 4. 오행 강약 (`RULE_ELEMENT_001`, `RULE_MOONCMD_001`, `RULE_DAYMASTER_001`)

천간 8개와 지장간을 합쳐 오행을 센다. **숫자만 세지 않는다.**

### 4.1 지장간 표 (`RULE_HIDDEN_001`)

《三命通會》의 통월(通月) 표를 쓴다. 가중치는 고정이며 **코드 상수**로 선언되어 있다.

| 등급 | 가중치 | 예: 寅 → 木 丙 / 戊 / 甲 |
| --- | --- | --- |
| 본기 | 1.0 | |
| 중기 | 0.5 | |
| 여기 | 0.3 | |

### 4.2 월령(月令) — 데이터다 (`RULE_MOONCMD_001`)

월령은 **전승(傳勝) 규칙만으로 유도되지 않는다.** 그것은 데이터다.
`MOON_COMMAND_TABLE` 이 `core/constants/stems.ts` 에 상수로 들어 있다.
계절 키 8개(초봄·봄·여름·晩여름·가을·겨울 등)를 모두 담는다.

`SEASON_WANG` 은 그 계절에 강한 오행을, `PHASE_WEIGHT` 는 旺相休囚死의
가중치(1.2 / 0.6 / 0.2 / −0.2 / −0.6)를 준다. 후자는 모듈 안에만 있고 화면에 내지 않는다.

### 4.3 일간 강약 판정 (`RULE_DAYMASTER_001`)

```
지지점 = ±1.5        |x| > 1.5 → 신강 / 신약
                        그 사이 → 중화
```

판정 근거(월령·계절·비겁·식상·재성·관살·인성의 기여)를 **모두 문장으로 남긴다.**
집계 점수는 계산에만 쓰고 화면에 내지 않는다. (즉 "87점" 같은 숫자가 나올 수 없다)

## 5. 용신·희신 (`RULE_YONGSHIN_001`)

**규칙은 하나뿐이다.** 세WEI를 섞지 않는다.

| 일간 강약 | 용신 | 희신 |
| --- | --- | --- |
| 신강 | 식상(食傷) | 재성(財星) |
| 신약 | 인성(印星) | 비겁(比劫) |
| 중화 | **가장 약한 오행** — 그 오행이 인성 계열이면 인성, 아니면 식상 | 용신과 같은 계열에서 가장 약한 것 |

중화일 때의 "가장 약한 오행"은 분포에서 고르되, 판정 과정을 **모두 문장으로 남긴다.**

결정 하나하나가 이렇게 기록된다.

```
ruleId        RULE_YONGSHIN_001
criteria      (무엇을 보고)
result        (무엇이 나왔는지)
interpretation(명리학에서 무슨 뜻인지)
```

즉 **기준 → 결과 → 규칙 → 해석** 으로 언제든 되짚을 수 있다.

## 6. 십신 · 십이지운성

### 6.1 십신 (`RULE_TENGOD_001`)

일간과 대상 천간의 오행 관계(생극제화)와 음양이 같은지로 정한다.
코드에는 `TEN_GODS` 로 상수로 들어 있고, 다섯 묶음(`TEN_GOD_GROUP`)으로 묶는다.

| 묶음 | 구성 | 성질 |
| --- | --- | --- |
| 비겁(比劫) | 비견(比肩) · 겁재(劫財) | 나와 같은 기운 |
| 식상(食傷) | 식신(食神) · 상관(傷官) | 내가 만들어 내보내는 것 |
| 재성(財星) | 정재(正財) · 편재(偏財) | 내가 다루고 쓰는 것 |
| 관성(官星) | 정관(正官) · 편관(偏官, 칠살) | 나를 다루는 통제 |
| 인성(印星) | 정인(正印) · 편인(偏印,枭神) | 나를 북돋는 것 |

> 오행 생극제화 관계표는 `core/elements/elementBalance.ts` 의 `GENERATES` / `CONTROLS` 한 곳에만 있다.
> (`木 → 火 → 土 → 金 → 水 → 木`, `木 → 土 → 水 → 火 → 金 → 木`)
> 관계를 설명하는 문장은 고전 명리 용어(식상·인성·재성·관살·비화 등)로 쓴다.

### 6.2 십이지운성 (`RULE_STAGE_001`)

**양간은 순행, 음간은 역행**한다. 시작 지지는 아래 표를 쓴다.

| 천간 | 갑 | 을 | 병 | 정 | 무 | 기 | 경 | 신 | 임 | 계 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 시작 | 亥 | 午 | 寅 | 酉 | 寅 | 酉 | 巳 | 子 | 申 | 卯 |

## 7. 간(干支)의 작용 (`RULE_INTERACT_*`)

합·충·형·파·해를 **구조로 저장**한다. 문장으로 뭉개지 않는다.

```ts
{ type, participants, description, interpretation, ruleId, ... }
```

- `participants` 는 어느 기둥끼리의 관계인지 함께 남는다. (원국↔원국, 원국↔대운, …)

| 종류 | 규칙 ID |
| --- | --- |
| 천간 5합 | `RULE_INTERACT_STEM_001` |
| 지지 6합 | `RULE_INTERACT_BRANCH_001` |
| 삼합(三合) | `RULE_INTERACT_TRIPLE_001` · `_002` |
| 방합(方合) | `RULE_INTERACT_DIRECTION_001` · `_002` |
| 六冲 | `RULE_INTERACT_CLASH_001` |
| 三刑 | `RULE_INTERACT_PUNISH_001` · `_002` · 자형 `_SELF_001` |
| 六破 | `RULE_INTERACT_BREAK_001` |
| 六害 | `RULE_INTERACT_HARM_001` |

### 반합은 완성된 합과 다르다

세 지지가 모이면 삼합(三合)·방합(方合)이 완성되고, 두 지지만 모이면 **반합(半合)** 이다.
**같은 종류라도 힘이 다르다.** 이 구분은 `core/interactions/` 가 `Interaction.strength` 에
박아 두었고, 해석 층은 그 값을 그대로 쓴다. (거기서 다시 정하지 않는다)

| 형태 | 세기 |
| --- | --- |
| 반합(두 자) | 1 — 旺(장간)을 포함하면 2 |
| 반방합(두 자) | 1 |
| 완성 삼합 · 완성 방합 (세 자) | 3 |
| 지지합 · 천간합 | 1 · 2 |
| 冲 · 刑 · 害 · 破 | 3 · 2 · 2 · 1 |

이 구분이 빠지면 반합이 완성 합과 똑같이 세어져 **모든 날이 "매우 두드러짐"** 이 된다.

대상 조합:

- 원국 ↔ 원국
- 원국 ↔ 대운 / 세운 / 월운 / 일운
- 대운 ↔ 세운
- 세운 ↔ 월운

## 8. 대운 (`RULE_DAEUN_001` ~ `_003`)

### 8.1 기산(起算)

```
기산 나이 = 생일과 인접한 節 까지의 일수 ÷ 3
```

1일 = 4개월 = 1/3년 이므로 **3일 = 1년** 으로 바꾼다.

- 순행 → **다음 節** 까지의 일수
- 역행 → **이전 節** 으로부터 지난 일수

### 8.2 순역

성별이 있으면 **성별순역법**. 없으면 **간지순역법**. 사용한 기준은 `directionRule` 에 기록한다.

### 8.3 기산 이전 (`RULE_DAEUN_001`)

아직 대운이 시작되지 않았으면 대운 자리를 비워 두고 `daeunAvailable: false` 로 표시한다.
빈 대운을 임의로 채우지 않는다. **이 상태도 설명 없이 지나가지 않는다.**
해석에 "대운 기산 전" 이라는 제한 통지가 먼저 붙는다.

## 9. 운의 계층 (`RULE_HIERARCHY_001`)

```
원국 → 대운 → 세운 → 월운 → 일운
```

**아래 계층만 따로 해석하지 않는다.** 낮은 계층은 반드시 위 계층과 함께 읽는다.

| 계층 | 가중치 |
| --- | --- |
| 원국 | 1.0 |
| 대운 | 1.0 |
| 세운 | 0.9 |
| 월운 | 0.7 |
| 일운 | 0.5 |

드릴다운 순서는 **일운 → 월운 → 세운 → 대운 → 원국** 으로 거꾸로 내려간다.

## 10. 해석의 강약과 방향 (`RULE_INTENSITY_001`)

신호마다 고정된 세기가 붙는다(1 / 2 / 3). 여기에 계층 가중치를 곱하고,
**비율**로 바꾼 뒤 구간에 넣는다.

### 10.1 한 계층은 항목 하나에 한 번만 더한다

같은 항목에 여러 신호가 붙어도 **계층마다 가장 강한 신호 하나만** 더한다.

한 계층에서 십신·오행·십이지운성이 같은 항목으로 각각 말할 수 있다. 그것을 그대로 더하면
계층이 많은 항목일수록 합계가 불어나고, 결과적으로 **모든 날이 "매우 두드러짐"** 이 된다.

### 10.2 합계를 비율로 바꾼다

절댓값 합계만으로는 항목끼리 비교할 수 없다. 말하는 계층 수가 다르기 때문이다.

```
비율 = (계층별 최대 신호값의 합) ÷ (존재하는 계층마다 최대 세기 3씩의 합)
```

총운은 다섯 계층이 모두 말하므로 천장이 높고, 직업·사업운은 관성이 걸린 날만 말하므로
낮다. 비율로 바꾸면 항목끼리도 날짜끼리도 **같은 눈금**으로 비교된다.

### 10.3 구간

| 비율 | 표시 |
| --- | --- |
| ≤ 0 | 두드러짐이 약함 |
| < 0.25 | 약간 두드러짐 |
| < 0.45 | 보통 |
| < 0.75 | 뚜렷함 |
| 그 밖 | 매우 두드러짐 |

이 숫자는 임의로 고른 것이 아니다. 여러 사주에서 1년 365일을 돌려 나온 비율 분포를 보고 정했다.
(대략 p10 0.1 · 중간값 0.35 · p90 0.6 부근이 각각 약함 · 보통 · 뚜렷함 에 걸린다)

방향은 상승·유지·하락·변화·중립 다섯 가지다.
중립 판정 폭도 이 사주의 계층 구성에 비례해 정한다. (고정값을 쓰면 신호가 많은 항목은
늘 상승, 적은 항목은 늘 중립이 된다)

**집계값은 화면에 내지 않는다.** 이분법("좋다/안 좋다")으로 줄이지도 않는다.
신호가 약하면 "특별한 신호가 두드러지지 않습니다" 라고 그대로 말한다. (`RULE_NEUTRAL_001`)

**해석 문장에는 그 근거가 반드시 옆에 붙는다.** 근거가 없는 해석은 만들어지지 않는다.

## 11. 오늘의 운세 항목 (`RULE_TOTAL_001` 등)

여덟 항목은 이 순서로 고정된다.

```
총운 · 재물운 · 직업·사업운 · 애정운 · 대인관계운 · 학업·성장운 · 건강운 · 이동·변화운
```

각 항목마다 **해석** 과 **분석 근거** 를 나누어 보여준다.

- 해석: 무슨 일이 생길 수 있는가
- 분석 근거: 어떤 규칙이, 어떤 기둥에서, 왜 이렇게 나왔는가 (규칙 ID · 계층 · 강약 · 방향)

### 항목마다 무엇이 말하는가

| 항목 | 주로 말하는 것 |
| --- | --- |
| 총운 | 원국 구조 · 각 운의 용신 오행 여부 · 십이지운성 · 반합/삼합 |
| 재물운 | 재성(재)· 식상(재를 생함) |
| 직업·사업운 | 관성(관살)· 책임과 압박 |
| 애정운 | 지지합· 천간합 · 재성 |
| 대인관계운 | 비겁 · 형(刑)· 해(害) |
| 학업·성장운 | 인성(印星)· 식상(표현) |
| 건강운 | 원국의 오행 빈핍 + 각 운의 십이지운성(왕쇠 단계) |
| 이동·변화운 | 충(冲)· 파(破) |

**십신 신호는 총운을 끌어당기지 않는다.** 십신은 다섯 계열 어디에나 걸리므로
총운까지 넣으면 어떤 날이든 다섯 계층 전부에서 총운 신호가 생겨
총운이 늘 최댓값에 붙는다. 총운은 위 표처럼 다른 것들이 말한다.

### 반드시 앞에 붙는 제한 통지

1. **시주 미상** — 시주를 못 계산했을 때
2. **대운 기산 이전** — 아직 대운이 없을 때

이 둘은 **절대로 잘리지 않는다.** 신호에서 뽑은 주의점으로 채워 넣지 않는다.
(신호에서 뽑은 주의점은 최대 `SIGNAL_CAUTION_LIMIT = 6` 개로 제한한다)
