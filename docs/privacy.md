# 개인정보 보호

Myeong 은 **계산과 메일 전송만** 한다. 저장 · 전송·집적 · 분석을 하지 않는다.
이 문서는 그 약속을 어떻게 지켰는지 적는 곳이다.

---

## ⚠️ 먼저 읽어야 할 것

### 저장소에 개인 정보를 넣지 않는다

**출생 정보 · 이름 · 메일 주소 · 비밀번호를 저장소에 커밋하지 않는다.**
파일이어도 안 된다. 커밋 이력은 지우기 어렵다.

금지하는 것:

- 출생 날짜·시간·지역을 코드에 쓰는 것
- 실제 주소나 계정을 테스트 픽스처에 넣는 것
- 계산 결과를 저장소에 붙여 넣는 것 (PR 본문 · 이슈 · 릴리스 노트 포함)
- 비밀값을 `package.json` 이나 `.env.example` 에 실제로 채워 넣는 것

시험용 값은 **눈에 띄게 가짜**로 쓴다.

```ts
// 좋은 예 — 가짜 주소
{ BIRTH_PLACE: "서울특별시/서대문구", EMAIL_USERNAME: "someone@example.com" }
```

### GitHub 의 비밀값 마스킹에 기대지 않는다

GitHub Actions 는 비밀값처럼 보이는 문자열을 로그에서 가려 준다. 하지만:

- 마스킹은 **우연히 비슷한 문자열까지** 가릴 수 있다.
- 변환·분할된 값은 **그대로 로그에 남는다.**
- 셸이 명령줄 인자로 받은 값은 프로세스 목록에 남는다.

그래서 이 프로젝트는 **마스킹이 있어도 안전하도록** 설계한다.
즉 **아예 로그에 나오지 않게** 만든다. (아래 §2)

## 1. 수집하는 정보

### 웹 화면

| 항목 | 보관 위치 | 전송 여부 |
| --- | --- | --- |
| 출생 정보 (양력/음력·윤달·시진·자시 기준·출생지·성별) | 브라우저 `localStorage` | **없음** |
| 화면 설정 (테마 등) | 브라우저 `localStorage` | **없음** |

`localStorage` 에 저장되는 정보는 **이 브라우저의 이 기기 안에만** 있다.
서버로 나가지 않고, 동기화되지 않고, 다른 기기에 옮겨 가지 않는다.

언제든 **설정 화면에서 직접 지울 수 있다.** 지우면 남는 것이 없다.

### 이메일

GitHub Actions 가 하루에 한 번 돌아와 **저장소 Secrets** 에서 출생 정보와 메일 계정을 읽는다.
그 값들은 **그 실행의 메모리에만** 있다. 실행이 끝나면 사라진다.

| 위치 | 값 | 비고 |
| --- | --- | --- |
| 저장소 | 없음 | 결과를 커밋하지 않는다 |
| Actions 아티팩트 | 없음 | 아티팩트를 올리지 않는다 |
| Actions 캐시 | 없음 | 캐시를 쓰지 않는다 |
| Actions 로그 | 단계 이름만 | 아래 §2 |

### 수집하지 않는 정보

- 이름 · 연락처 · 주소지 (출생지의 시/군/구를 제외)
- 이메일 본문 보관
- 접속 기록 · 분석 정보 · 쿠키 · 추적 스크립트
- 기기 정보 · 위치 정보

## 2. 로그에 남는 것

이메일 작업이 남길 수 있는 줄은 **네 줄뿐**이다. 코드에서 상수로 고정되어 있다
(`email/main.ts` 의 `ALLOWED_LOGS`) 그리고 **테스트가 그 목록을 그대로 검사한다.**

```
Myeong Core started
Calculation completed
Email sent successfully
Email sending failed: <사유>
```

`<사유>` 에는 오류 종류 · SMTP 단계 · SMTP 코드만 온다. 값은 아니다.

**절대 남기지 않는 것:**

- 출생 날짜 · 시간 · 지역
- 간지 (年/月/日/時 干支) — 기둥 전체가 아니라 **한 글자도**
- 오행 분포 · 십신 · 용신
- 운세 문장 (해석 · 근거)
- 메일 주소 · 발신자 · 수신자
- 메일 본문 · 제목
- 비밀번호 · 인증 토큰

SMTP 오류를 다룰 때도 같다. 서버가 "인증 실패: <계정>" 이라고 말해도 **그 원문을 로그에 쓰지 않는다.**
단계 이름과 응답 코드만 남긴다.

이 규칙은 사람이 지키기로 한 약속이 아니라 **테스트가 검사한다.**
(`tests/email.test.ts` — `email/*.ts` 소스를 읽어 `console.*` 호출이 상수만 넘기는지 확인한다)

## 3. 계산 결과가 남지 않게 하는 방법

이메일 작업은 결과를 **어디에도 쓰지 않는다.**

- 파일을 쓰지 않는다. (`writeFileSync` 等 사용 없음 — 테스트로 확인)
- 아티팩트를 올리지 않는다.
- 캐시를 쓰지 않는다.
- 실행이 끝나면 프로세스가 끝난다. 남는 상태가 없다.

웹 화면도 같다. 계산은 브라우저 메모리에서 일어나고 DOM 에 그려질 뿐이다.

> **결과를 남기고 싶다면 코드를 고쳐야 한다.**
> 우연히 새는 일이 없다.

## 4. 웹 화면의 보안 설정

`index.html` 의 CSP `meta` 태그가 아주 조하다.

```
default-src 'none'
script-src 'self'
style-src 'self'
img-src 'self' data:
connect-src 'none'
form-action 'none'
base-uri 'none'
object-src 'none'
```

핵심은 **`connect-src 'none'`** 이다. 네트워크 요청 자체가 막혀 있다.
계산에 외부 통신이 필요 없다는 사실이 **브라우저가 강제한다.**

오행 색상은 `data-element` 속성과 CSS `color-mix()` 로만 만든다.
JS 로 `style` 속성을 끼워 넣지 않기 때문에 `style-src 'unsafe-inline'` 이 필요 없다.

**`frame-ancestors` 는 넣지 않는다.** `<meta>` 에서는 무시된다.
클릭재킹 방어는 GitHub Pages 응답 헤더에서 해야 한다. (Pages 는 사용자 정의 헤더를 직접 못 정하므로,
자동화 도구나 Pages 대신 정적 호스팅을 쓸 때 넣는다.)

> **외부 폰트 · 외부 CDN · 외부 스크립트를 쓰지 않는다.**
> 오프라인에서도 계산이 되고, 번들이 작고, 언제 무엇이 실행되는지 전부 알 수 있다.

---

## 5. 출생信息安全 저장소로 보내지 않는 이유

- **계산에 필요 없다.** 전부 브라우저 안에서 끝난다.
- 서버로 모으면 그 서버를 지켜야 한다. 그러지 않아도 되는 일을 늘린다.
- 사용자가 자기 정보를 직접 지우고 직접 내보낼 수 있는 편이 낫다.

## 6. 다뤄야 할 위험

| 위험 | 어떻게 다룬다 |
| --- | --- |
| 출생 정보가 계산 착오로 오해 | 화면에 계산 근거(절기 시각 · 규칙 ID)를 함께 보여준다 |
| 운세에 기대어 중요한 결정을 내린다 | 모든 화면에 명리학 고지를 둔다. "과학적으로 검증된 방법이 아님"을 반복해 말한다 |
| 출생 시간을 모르는 데서 억지로 추정 | 시주를 계산하지 않고 **제한 통지**를 먼저 붙인다 |
| 대운 기산 전 상태를 모호하게 넘김 | `daeunAvailable: false` 를 명시하고 제한 통지를 붙인다 |
| 플랫폼이 비밀값을 로그에 새긴다 | 마스킹에 기대지 않고 애초에 로그에 안 쓴다 |
| 입력 오류로 사용자가 혼란 | 사람이 읽을 문장으로 알린다. 스택 트레이스를 보여주지 않는다 |

## 8. 점검 목록 (배포 전에 확인한다)

- [ ] 저장소 전체에 실제 이름 · 주소 · 계정 · 비밀번호가 없다
- [ ] 테스트 픽스처 값이 눈에 띄게 가짜다
- [ ] `tests/email.test.ts` 의 소스 감사 테스트가 통과한다
- [ ] 워크플로에 아티팩트 업로드 · 캐시가 없다
- [ ] 로그 문자열이 `ALLOWED_LOGS` 네 줄뿐이다
- [ ] `dist/` 에 개인 결과 파일이 없다
- [ ] PR · 이슈 · 릴리스 노트에 개인 결과가 없다
- [ ] README 의 Secrets 안내에 "저장소에 넣지 말 것" 경고가 있다

## 9. 바꾸지 않을 것

아래를 추가 기능으로 넣지 않는다. (요청이 없는 한)

- 로그인 · 회원가입 · 데이터베이스 · 서버
- 분석 스크립트 · 광고 · 서드파티 위젯
- 개인 결과를 저장하거나 공유하는 기능
- 출생 정보를 서버로 보내는 경로

계산은 브라우저에서, 메일은 그날 그 자리에서, 남기는 것은 없다.
